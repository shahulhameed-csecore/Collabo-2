# InfluencerTrack Backend: Complete Architecture Report

This document serves as the comprehensive engineering record of everything built for the InfluencerTrack backend from inception to its current production-ready state.

## 1. Core Stack & Infrastructure
* **Framework:** FastAPI (Python 3.10+) leveraging asynchronous routing for high concurrency.
* **Database & Auth:** Supabase (PostgreSQL).
* **AI Engine:** Google Gemini 3.5 Flash via the modern `google-genai` SDK.
* **Server:** Uvicorn with automatic reload during development and explicit port binding (`$PORT`) for production.
* **Infrastructure-as-Code:** Fully mapped via `render.yaml` for instant deployment on Render.com, alongside a tightly pinned `requirements.txt` to prevent dependency rot.

## 2. Security & Zero-Trust Architecture
* **Supabase JWT Authentication:** The API natively validates Supabase Bearer tokens using a custom `HTTPBearer` security dependency. 
* **Custom User Wrapper:** To prevent strict Pydantic `gotrue` model conflicts, we implemented an `AuthenticatedUser` class to safely bundle the database user context and JWT token.
* **Row Level Security (RLS) Forwarding:** The backend does not use a master "God Mode" key to query the database. Instead, every request to Supabase dynamically instantiates a client using the *exact JWT of the caller*. This guarantees that Postgres RLS rules are respected, making it mathematically impossible for Brand B to view or delete Brand A's campaigns, regardless of Python logic flaws.
* **Global Exception Handler:** Intercepts all unhandled exceptions, logs the full stack trace to standard output for developers, but returns a generic, safe `500 Internal Server Error` to the client. This strictly prevents sensitive code architecture from leaking to the internet.
* **Dynamic CORS:** Controlled via the `ALLOWED_ORIGINS` environment variable in `config.py`, which is automatically parsed into a strict security list.

## 3. Data Integrity & Validation (Pydantic V2)
All incoming and outgoing data is strictly filtered and validated:
* **String Constraints:** Every text field has a defined `max_length` (e.g., 255 for names, 5000 for notes) to prevent Denial of Service (DoS) via massive payload injections.
* **Enum Validation:** The campaign `status` field is strictly typed to a `CampaignStatus` Enum (`draft`, `active`, `completed`, `cancelled`). Any deviation results in an automatic HTTP `422 Unprocessable Entity` rejection.

## 4. The AI Extraction Engine (`app/services/gemini.py`)
This is the core "Human-in-the-Loop" pipeline, transforming raw screenshots into structured JSON.
* **Dynamic Image Optimization:** Before sending an image to Gemini, the backend automatically converts it to `RGB` format, resizes it using Lanczos resampling to a maximum dimension of 1024x1024, and compresses it to an 85% quality JPEG in-memory. This drastically reduces API latency, saves bandwidth, and cuts token costs.
* **Robust Fallback Mechanism:** If the Gemini API experiences a timeout, throws an error, or the JSON decoding fails, the server *will not crash*. Instead, it catches the error and returns a predefined fallback dictionary with `requires_human_review = True`, prompting the user to type the details manually.

## 5. Complete API Surface (Endpoints)

### Utility
* **`GET /` (Health Check):** Returns the operational status and the current runtime `ENVIRONMENT`.

### AI Extraction
* **`POST /extract/`:**
  * Validates the file is indeed an image (`content_type`).
  * Enforces a hard **5MB file size limit**.
  * **Rate Limiting:** Guarded by `slowapi` to allow a maximum of **10 requests per minute** per user, preventing malicious bot spam and API quota exhaustion.
  * Secured entirely behind `Depends(get_current_user)`.

### Campaign Management (CRUD)
* **`GET /campaigns/`:** Retrieves campaigns. Includes mandatory **Offset/Limit Pagination** (default limit 50, max 100) to ensure the server remains performant even if a brand stores thousands of campaigns.
* **`POST /campaigns/`:** Creates a new campaign. Manually extracts the `user.id` from the secure JWT context and injects it into the Postgres payload to guarantee the row is assigned safely.
* **`PUT /campaigns/{id}`:** Allows for full updates of a campaign profile schema.
* **`PATCH /campaigns/{id}/status`:** A highly specialized state-machine endpoint that only accepts a single `status` field, cleanly moving a campaign through its lifecycle.
* **`DELETE /campaigns/{id}`:** Completely deletes a campaign. Bound by RLS to ensure you can only delete what you own. Returns a `404` if the campaign doesn't exist or access is denied.
